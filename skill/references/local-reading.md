# 本地材料读取

保持普通 Chat 交付、C2C 提供已授权材料、Codex 集成和真实验证的现有分工。本指引不扩大目录、写入或执行权限。

## 先确认能力

读取当前 `workspace_info`，核对工作区身份与 `fileReading`。旧版本可能没有这个字段；工具列表与真实返回优先。只有当前会话确实暴露 `read_files` 时才用批量接口，不能用本地已改技能或服务器源码代替聊天端工具快照。

只有旧文本入口时，读取 CSV、JSON 或源代码的原文不证明能够解析 Excel、PDF、图片、数据库或运行测试。新版的材料工具仍需要本地解析运行时和正确配置；以实际调用成功及覆盖范围为准。

## 取得最少且准确的输入

1. 用目录、文件路径和搜索定位输入，不让 Codex 先复制整份源码或长日志。
2. 一次需要函数、调用者、测试和配置时，优先将最多 8 个独立范围放入 `read_files.items`。保留默认聚合预算，按需续读。
3. 每项结果分别判断 `ok`。失败项没有可采用正文，不影响其他成功项；不能把失败当成空文件。
4. `structuredContent.nextIndex` 只表示尚未返回的批量项；用原 `items` 和这个 `offset` 继续。每项 `file.nextStartLine` 表示该文件正文的下一行，两者不能互换。
5. 同一文件继续读取时，使用上一结果的 `sha256` 填入 `expected_sha256`。这是原始完整文件字节的摘要，包含原始编码和换行；不是展示正文摘要，也不是整批原子快照。版本变化时重新定位受影响文件，不拼接新旧页。

## 编码与预算

- `auto` 只依据 BOM 或严格 UTF-8，不猜中文编码。无 BOM 的 UTF-16 或已知 GBK/GB18030 来源需要显式 `encoding`；未知编码先查来源，不把乱码用于计算、修改或结论。
- UTF-16 BOM 支持不等于二进制文件可读。真实二进制仍拒绝。
- `RANGE_TOO_LARGE`、`OUTPUT_TOO_LARGE` 表示范围或序列化结果超限。普通多行文件缩小行范围；一条极长行无法靠重复同一请求取得完整结果，应报告需专用切片能力。
- `truncated` 或续读位置表示还有未返回内容，不能宣称完整审阅。搜索当前仍会跳过超过 2 MiB 的文件；无匹配不证明大型文件无相关内容。

## 完整产物与采用

一次工作包只给目标、准确输入引用/版本、一个完整产物和必要验证。Chat 报告实际生成与运行了什么；Codex 采用同一份成果，只补目标环境验证。已经完成且输入未变的工作不双方重做。

先用 `list_material_roots` / `list_materials` 找已授权材料；需要多个输入时用 `context_manifest` 取得当前摘要与变化，只有必要时读取正文。模型不能自行登记根目录。

`read_material` 先 `overview`，再按 PDF 页、Word 正文块、Excel 单元格范围或图片选择 `read` / `image`。原生图片、结构化文档和双向附件通道须分别取得实际客户端证据：模型看到了图、计算工具能打开原件、本地收到同一份产物是三个不同条件。扫描页无文本不当空白页，公式缓存缺失不填零，Word 块号不当固定页码。

需要完整原件时用 `export_material` 返回的短期认证资源链接，由宿主取得原件；不能让模型抄写 base64。Chat 生成成果后将真实附件传入 `receive_deliverable.file`，宿主提供文件引用，不编造下载地址。收件箱必须已在本地启用且获 `artifacts.write` 权限；接收成功只表示候选落盘，Codex 核对回执摘要和输入版本后采用，不自动执行、覆盖或提交源码。旧只读授权不会因工具增加而自动变成写权限。

没有已验证通道时准确标记限制，不切换 Work、扩权或让老板手工搬长正文；继续当前可独立完成的工作。

只改技能文件不会更新 ChatGPT 的工具或技能快照。需要发布更新时按既有候选验证/切换流程执行；工具快照刷新、连接地址恢复与本地源码修改分别核验。
